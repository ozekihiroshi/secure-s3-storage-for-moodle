# Secure S3 Storage 0.6.0

This alpha release adds an administrator-only operational status page for the
course, database, and Moodle content backup domains. It shows the effective
non-secret S3 destination, enabled state, Moodle cron expression, previous and
next runs, failure delay, aggregate audit status, and the twenty most recent
transfer records.

Administrators can intentionally queue an enabled transfer from this page. The
web request never creates a backup or contacts S3. It submits a deduplicated
Moodle adhoc task, and Moodle Cron performs the work using the same locks,
configuration checks, AWS credential provider chain, and fail-closed transfer
logic as the scheduled task. Moodle's standard Scheduled tasks page remains the
single place for editing execution times.

Retention and deletion ownership is now explicit. Moodle automated-backup
settings control local course archive retention. The plugin preserves local
database artifacts, never deletes Moodle `filedir` content, and never deletes a
verified S3 object. Remote retention belongs in S3 Versioning and Lifecycle
rules scoped to the dedicated plugin prefix. This release does not add a web
restore or delete operation.

The release includes the existing independently controlled Moodle course,
database, and database-matched content recovery features. Database and content
transfers remain disabled by default. Content transfer requires the built-in
database producer so both domains share a recovery-set identifier. The external
database producer remains available for advanced process isolation but does not
produce content recovery sets.

The clean-ZIP release gate installs the self-contained plugin into an empty
Moodle 5.2.2 environment. It verifies course backup transfer and restore,
external and built-in database backup transfer, database-matched content
transfer, malformed-manifest and corrupt-payload rejection, isolated database
and `filedir` restoration, and Moodle File API access to restored content.
Moodle Plugin CI separately passes PHP lint, coding-style, PHPDoc, plugin
validation, upgrade-savepoint, and PHPUnit checks on MariaDB/PHP 8.2 and
PostgreSQL/PHP 8.4.

This remains an alpha release for controlled evaluation. It does not protect
`.env`, `config.php`, locally installed code, or external primary object
storage. Restore remains CLI-only and must target an isolated empty database
and content directory. Production deployment still requires a working Moodle
Cron, least-privilege runtime IAM credentials, a dedicated S3 prefix, storage
capacity and cost monitoring, and regularly rehearsed recovery procedures.
