# Secure S3 Storage 0.3.0

This alpha release adds a security-separated database backup artifact transfer
path alongside the existing Moodle course-backup transfer.

A deployment-controlled producer creates a consistent MariaDB dump, compresses
it, and publishes an exact versioned manifest. Moodle Cron receives only a
read-only artifact hand-off volume. The plugin rejects unknown manifest fields,
unsafe names, symlinks, hard-link aliases, boundary violations, size changes,
and SHA-256 mismatches. It uploads and verifies the payload first and publishes
`manifest.json` last so incomplete transfers are not advertised as recoverable.

Database credentials, dump execution, and restore credentials remain outside
Moodle PHP and plugin settings. Database transfer has its own setting and
scheduled task and remains disabled by default.

The clean-ZIP release gate installs the plugin into an empty Moodle 5.2.2
environment. It proves fail-closed rejection of an abnormal manifest and a
corrupt payload, local preservation, and absence of an S3 completion manifest.
It then produces a real MariaDB dump, transfers it to MinIO, downloads and
verifies it, restores it into a separate empty MariaDB instance, and reads the
restored database through a fresh Moodle image. The existing course backup,
download, checksum, and restore gate continues to pass.

This remains an alpha release for controlled evaluation. It does not yet back
up `moodledata`, configuration, locally installed code, or primary S3 content.
The companion `moodle-rescue` repository supplies the reference database
producer and isolated recovery gate.
