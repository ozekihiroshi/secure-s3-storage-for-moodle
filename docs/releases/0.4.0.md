# Secure S3 Storage 0.4.0

This alpha release adds a built-in MariaDB/MySQL database backup producer for
administrators who install only the Moodle plugin. Moodle Cron creates a
repeatable-read, read-only Moodle DTL XML export below the non-web-accessible
Moodle data directory, compresses and hashes it, atomically publishes a strict
version 2 manifest, and transfers the verified artifact to S3.

The external native-dump producer introduced in 0.3.0 remains available for
deployments that require stronger process and credential separation. Upgrades
from 0.3.0 deliberately retain external mode and keep database backup enabled
or disabled as already configured. To use the new built-in producer, an
administrator must explicitly select **Built-in Moodle producer**. Fresh
installations select built-in mode but still keep database backup disabled by
default.

Recovery remains an isolated CLI-only operation. The restore command rejects
the live database name and non-empty target databases, validates the manifest,
size, SHA-256 digest, and payload boundaries, and reads the target password only
from an environment variable. No database restore is exposed through a web
request.

The clean-ZIP release gate installs the plugin into an empty Moodle 5.2.2
environment. It verifies built-in production, abnormal version 2 manifest and
corrupt payload rejection, local preservation, absence of rejected S3 objects,
S3-compatible download, and restoration into a separate empty database. The
existing external database artifact and Moodle course-backup gates also remain
in place.

This remains an alpha release for controlled evaluation. It does not back up
`moodledata`, configuration, locally installed code, or primary S3 content.
