# Secure S3 Storage 0.5.0

This alpha release adds independently controlled backup of the existing Moodle
`moodledata/filedir` content pool. It does not move primary Moodle file
storage to S3.

Each built-in database backup now captures a sorted content inventory inside the
same repeatable-read transaction and links both artifacts with one
`recoverysetid`. A bounded scheduled task validates canonical file-pool paths,
size, Moodle SHA-1, and SHA-256 before transferring immutable objects. Inventory
and completion manifests are published only after remote read-back verification.

Content transfer remains disabled by default and requires the built-in Moodle
database producer. Administrators must validate IAM scope, S3 capacity and
cost, bucket versioning or immutability, and isolated recovery before enabling
it. The external database producer remains available for advanced isolation but
does not produce content recovery sets.

Restore remains CLI-only. The command requires an empty isolated target,
validates the matching database and content contracts, reconstructs canonical
`filedir` paths, and refuses the live Moodle data directory. No content or
database restore is exposed through a web request.

The clean-ZIP release gate installs the plugin into an empty Moodle 5.2.2
environment, produces one database-matched recovery set, transfers it through
MinIO, downloads it, and restores the database and content into isolated
targets. Invalid manifests and checksum-corrupt database or content payloads
must fail closed without publishing completion manifests or modifying the
original Moodle content pool.
